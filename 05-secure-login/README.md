# ЦИТАДЕЛЬ — вход с двухфакторной защитой

Экран входа в личный кабинет или админку: почта и пароль, затем шестизначный
код из приложения на телефоне. Даже если пароль утёк, без телефона владельца
в аккаунт не попасть.

**Кому продавать:** всем, у кого есть вход на сайт — онлайн-школам, клиникам
с личным кабинетом, магазинам с админкой, CRM, закрытым клубам.

## Как попробовать

1. Откройте страницу, введите любую почту и пароль не короче 10 символов.
2. На втором шаге возьмите код с телефона справа. Можно просто нажать на код —
   он впишется в ячейки сам.
3. Или подключите **свой настоящий телефон**: блок «Подключить свой телефон» →
   «Скопировать ключ» → в Google Authenticator, Яндекс Ключ, Microsoft
   Authenticator, Aegis или 2FAS выберите «Ввести ключ вручную», тип «по времени».
   Коды в телефоне совпадут с экраном — это настоящий стандарт TOTP.

## Что внутри

**Защита**
- Коды по стандарту TOTP (RFC 6238), проверено на официальных тестовых векторах.
- Окно ±30 секунд: если часы телефона немного отстают, код всё равно подойдёт.
- Один и тот же код дважды не принимается, даже в пределах своих 30 секунд.
- После пяти ошибок — блокировка на 30 секунд, потом 60, 120… до 8 минут.
  Кнопка «Назад» блокировку не сбрасывает.
- Проверка надёжности пароля; пароль стирается из памяти страницы сразу после первого шага.
- Content-Security-Policy `connect-src 'none'; form-action 'none'`: в демо страница
  физически не может ничего никуда отправить. В рабочем режиме сервер меняет это
  на `connect-src 'self'` — запросы уходят только на свой домен.
- Весь текст выводится через `textContent` — страница работает под Trusted Types,
  вставить на неё чужой HTML нельзя.

**Удобство**
- Код можно вставить целиком (Ctrl+V) в любую ячейку.
- На телефоне код из СМС подставляется сам (`autocomplete="one-time-code"`).
- Стрелки и Backspace ходят по ячейкам, лишние символы отбрасываются.
- Показать/скрыть пароль, понятные сообщения об ошибках на русском.

**Анимации**
- Щит сканирует во время проверки, трясётся и краснеет от ошибки,
  при успехе дужка замка откидывается и рисуется галочка.
- Цифры в ячейках выпрыгивают, при успехе по ним проходит зелёная волна.
- Телефон с кольцом-таймером: код переворачивается при смене, кольцо краснеет
  за 5 секунд до конца.
- Фон: бегущая сетка, луч сканера, светящиеся пятна.
- При системной настройке «уменьшить движение» анимации отключаются.

## Честно про демо

В этом демо секрет лежит в браузере (localStorage) и код проверяется прямо на
странице — так витрина работает без сервера. **На рабочем сайте так нельзя:**
секрет из браузера может прочитать кто угодно.

Настоящий вход уже написан и лежит в папке `server/`. Запустите его — и та же
страница начнёт работать по-настоящему:

```
node server/server.js --add-user ваша@почта.ru
node server/server.js 8080
```

Сервер сам дописывает странице входа атрибут `data-api`, и она переключается
в рабочий режим: макет телефона убирается, код проверяет сервер, после входа
открывается закрытый кабинет `/kabinet/`. Файлы на диске при этом остаются
демоверсией — на статическом хостинге всё работает как витрина.
Подробности: `server/README.md`. Короткий учебный пример без сессий и кабинета —
`server-example.js`.

## Что уже сделано за вас на сервере

Менять `auth.js` не нужно: он умеет оба режима сам. Сервер из папки `server/`
берёт на себя всё остальное:

1. **Заведение входа.** `--add-user` создаёт ключ (20 случайных байт), кладёт его
   в хранилище и печатает ссылку `otpauth://` для приложения-генератора.
2. **Первый шаг.** `POST /api/login` сверяет пароль с хешем scrypt и выдаёт
   «половину сессии» на пять минут. В кабинет она не пускает.
3. **Второй шаг.** `POST /api/2fa` проверяет код по ключу с сервера, меняет номер
   сессии и только теперь открывает доступ.
4. **Закрытые страницы.** Кабинет лежит в `server/private/` — вне открытой папки
   сайта. Без полной сессии сервер отвечает переадресацией на вход.

Что стоит добавить, если продаёте это клиенту всерьёз:

- **резервные коды** — 8–10 одноразовых на случай потери телефона, хранить хешами;
- **подтверждение при включении 2FA**: включать её только после первого верного
  кода, иначе пользователь запрёт сам себя;
- **база данных вместо JSON-файла** — поля те же;
- **HTTPS и `FORCE_SECURE=1`** — без этого пароль и код идут открытым текстом.

Короткий учебный пример проверки кода, без сессий и кабинета:

```
node 05-secure-login/server-example.js --selftest
```

Полная проверка рабочего сервера — 17 сквозных тестов:

```
node server/selftest.js
```

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | разметка трёх шагов, телефона и уведомлений |
| `css/auth.css` | каркас: раскладка, поля, ячейки, телефон, адаптив от 375 px |
| `css/theme.css` | цвета, фон и сцена со щитом — только это меняется под сайт |
| `js/totp.js` | генерация и проверка кодов (Web Crypto), работает и в Node |
| `js/auth.js` | логика шагов, ячеек, блокировок и телефона |
| `server-example.js` | проверка кода на сервере с блокировками по аккаунту и по адресу |

## Тот же вход внутри каждого сайта

Экран входа стоит не только здесь. В каждом сайте портфолио есть папка `login/`
со своей темой — одинаковый движок, разный дизайн и разная сцена:

| Адрес | Кабинет | Что происходит при верном коде |
|---|---|---|
| `01-barbershop/login/` | мастера барбершопа | барберский шест раскручивается, ложится золотая галочка |
| `02-renovation/login/` | заказчик ремонта | замок-чертёж открывается, дужка откидывается |
| `03-kitchens/login/` | студия кухонь | дверцы шкафа распахиваются, внутри загорается галочка |
| `04-houses/login/` | стройка дома | в окнах включается свет и открывается дверь |
| `05-secure-login/` | витрина «ЦИТАДЕЛЬ» | щит раскрывается, замок снимается |

Файлы `css/auth.css`, `js/auth.js` и `js/totp.js` во всех папках одинаковые:
поправили здесь — скопируйте в остальные. Под сайт меняются только `theme.css`,
тексты в `index.html` и атрибуты `data-store`, `data-issuer`, `data-account` у `<body>`.
